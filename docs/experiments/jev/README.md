# Живые вызовы Jev

Здесь то, что **не удалось проверить** в облачной сессии: её egress закрыт политикой
окружения, `ai-gateway.vercel.sh` отвечает `connect_rejected`. На локальной машине всё
работает — это ограничение песочницы, а не проекта.

> **Промо-цена Jev заканчивается 25 сентября 2026.** До этого вход — $0.042 за миллион
> входных токенов, выход бесплатно. Весь прогон ниже стоит центы; после 25-го тоже
> недорого, но окно лучше не пропускать.

## Запуск

```bash
cd docs/experiments/jev
npm install
export AI_GATEWAY_API_KEY=vck_...        # ключ AI Gateway

node probe.mjs axes    # ← начните с этого
node probe.mjs det
node probe.mjs kin
```

Без SDK, чтобы видеть провод: `./raw.sh`

## Зачем именно это

**`axes` — двухосность `вес` / `натяг`.** Несущая гипотеза §5: это независимые оси, и
потому цена двумерна. «Метеорит тяжёл, но в него легко поверить; придворная интрига легка,
но против течения». Восемь утверждений покрывают все четыре угла; скрипт считает
корреляцию. **Если оси слиплись — двухосная цена схлопывается в одну шкалу, и §5 надо
переписывать целиком.** Это первое, что стоит узнать о проекте, и стоит оно одного прогона.

**`det` — детерминизм котировки** (пункт D разбора). §5 обещает воспроизводимую цену, §8
велит сэмплировать из распределения. Противоречие снимается, если распределение Jev
устойчиво: тогда цена берётся из `score`, который по типам SDK **уже есть
вероятностно-взвешенное среднее**, а сэмплинг остаётся только для решений мира.

**`kin` — различает ли модель роды.** §5 показывает Ember 91% против Flint 7%. Если приоры
родов не разводят вероятности, предпросмотр показывает шум, и на нём нельзя строить ни
цену, ни обещание игроку.

## Форма вызова

Взята из типов `ai@7.0.107` и `@ai-sdk/gateway@4.0.87`, не из документации:

```js
import { experimental_evaluate as evaluate } from "ai";

const r = await evaluate({
  model: "typesafe-ai/jev",
  state: { /* один общий state на все вопросы */ },
  questions: {
    вес:    { type: "score",   instructions: "...", criteria: ["шёпот", "молва", /* 2..10 уровней */] },
    охват:  { type: "choice",  instructions: "...", criteria: { двор: "описание", поселение: null } },
    верит:  { type: "boolean", instructions: "..." },
  },
});

r.answers.вес.score            // дробная позиция на шкале — УЖЕ взвешенное среднее
r.answers.вес.probabilities    // полное распределение по уровням
r.answers.верит.probability    // P(true) — это и есть noul
r.usage.inputTokens
```

Три расхождения с наброском в §5 архитектуры, которые сломают код при копировании:

1. **У каждого вопроса обязателен `instructions`** — в §5 его нет.
2. **`criteria` у `score` — упорядоченный массив**, у `choice` — объект `имя → описание`.
   В §5 у `score` записан массив, это верно; у `охват` тоже массив, а если это `choice` —
   нужен объект.
3. **Тип называется `boolean`, а не `noul`.** `noul` — имя в проводном формате TypeSafe;
   SDK отдаёт нейтральное `boolean` и кладёт вероятность в `probability`.
